# AWS Serverless Cloud Infrastructure & Security Dashboard

A serverless AWS application for tracking cloud infrastructure resources and their security review status.

This project demonstrates Infrastructure as Code (IaC), serverless application architecture, AWS service integration, REST-style API development, authentication and authorization, cloud security practices, observability, and automated frontend deployment using Terraform.

## Project Status

✅ **Core Application Complete**

The application is fully deployed and operational, including the frontend, REST-style CRUD API, authentication and authorization, persistent data storage, and application logging.

The frontend is hosted in a private Amazon S3 bucket and delivered over HTTPS through Amazon CloudFront using Origin Access Control (OAC). Amazon Cognito provides administrator authentication through OAuth 2.0 Authorization Code with PKCE, while API Gateway uses JWT authorization to protect resource-modifying API routes.

The infrastructure is fully managed with Terraform and has been validated through a complete destroy and redeploy cycle. Deployment-specific configuration, including API Gateway, Cognito, and CloudFront values, is automatically generated by Terraform for the frontend.

## Architecture

The application uses:

* **Amazon CloudFront** — Provides the public HTTPS endpoint and delivers frontend content.

* **Amazon S3** — Privately stores the dashboard HTML, CSS, JavaScript, and generated deployment configuration.

* **CloudFront Origin Access Control (OAC)** — Allows CloudFront to securely retrieve objects from the private S3 bucket.

* **Amazon Cognito** — Provides administrator authentication using Cognito Managed Login and OAuth 2.0 Authorization Code with PKCE.

* **Amazon API Gateway (HTTP API)** — Provides REST-style HTTP endpoints for the application.

* **API Gateway JWT Authorizer** — Validates Cognito-issued access tokens and restricts resource-modifying API routes to authenticated users.

* **AWS Lambda** — Handles API requests, input validation, and application logic.

* **Amazon DynamoDB** — Stores infrastructure resource and security review data.

* **Amazon CloudWatch Logs** — Provides Lambda application and execution logging with Terraform-managed log retention.

* **AWS IAM** — Provides Lambda execution permissions and least-privilege access to required AWS resources.

* **Terraform** — Provisions and manages the AWS infrastructure and generates deployment-specific frontend configuration.

* **HTML, CSS, and JavaScript** — Provides the browser-based dashboard, authentication workflow, and communication with the API.

                                     │

The S3 bucket blocks direct public access. Frontend objects are retrieved through CloudFront using Origin Access Control rather than exposing the bucket publicly.

Read operations are publicly accessible, while create, update, and delete operations require authentication. Cognito authenticates administrator users, and API Gateway validates the resulting JWT access token before allowing requests to protected routes.

## API

The application exposes the following REST-style endpoints:

| Method   | Endpoint          | Access        | Description                    |
| -------- | ----------------- | ------------- | ------------------------------ |
| `GET`    | `/resources`      | Public        | Retrieve all tracked resources |
| `GET`    | `/resources/{id}` | Public        | Retrieve a specific resource   |
| `POST`   | `/resources`      | Authenticated | Create a new resource          |
| `PATCH`  | `/resources/{id}` | Authenticated | Update an existing resource    |
| `DELETE` | `/resources/{id}` | Authenticated | Delete a resource              |

API responses use JSON with appropriate HTTP status codes and validation for malformed or invalid request bodies.

API Gateway CORS configuration permits requests from the deployed CloudFront frontend while retaining the localhost origin for development. The `Authorization` header is permitted for authenticated requests.

Default API Gateway throttling limits are configured at 10 requests per second with a burst capacity of 20 requests.

## Authentication and Authorization

Administrator authentication is provided by Amazon Cognito.

Self-service account registration is disabled. Administrative users are created separately rather than being provisioned through Terraform, preventing user credentials from being stored in Terraform configuration or state.

The browser uses the OAuth 2.0 Authorization Code flow with Proof Key for Code Exchange (PKCE) to authenticate through Cognito Managed Login.

After authentication, the frontend includes the Cognito-issued access token in protected API requests:

```text
Authorization: Bearer <access-token>
```

API Gateway validates the JWT before forwarding protected requests to Lambda.

Authorization is enforced at the API layer:

* `GET` operations remain publicly accessible.
* `POST` requires authentication.
* `PATCH` requires authentication.
* `DELETE` requires authentication.

This means access control does not depend solely on hiding administrative controls in the frontend.

## Deployment Configuration

The frontend requires deployment-specific values for API Gateway, Cognito, and CloudFront.

Rather than hardcoding AWS-generated identifiers into `app.js`, Terraform generates a `config.js` object during deployment.

The generated configuration provides values including:

```javascript
window.APP_CONFIG = {
  apiBaseUrl: "...",
  cognitoClientId: "...",
  cognitoDomain: "...",
  redirectUri: "..."
};
```

`index.html` loads `config.js` before the main application JavaScript, allowing `app.js` to use values generated from the current Terraform deployment.

This allows newly created AWS resource identifiers and endpoints to be automatically propagated to the frontend after infrastructure recreation.

## DynamoDB Design

The DynamoDB table uses `id` as its partition key for direct resource retrieval.

Secondary indexes are defined for:

* `environment`
* `owner`
* `securityReview`

These indexes represent potential access patterns for querying resources by operational or security-related attributes.

The current resource-listing operation uses a table scan because the dashboard retrieves the complete resource collection. Lambda IAM permissions are scoped to the DynamoDB operations currently required by the application.

## Observability

AWS Lambda writes application and execution logs to Amazon CloudWatch Logs.

The CloudWatch log group is managed by Terraform with a 14-day retention period, preventing application logs from being retained indefinitely.

Application logging records important resource lifecycle operations such as creation, updates, and deletion while allowing operational issues to be investigated through CloudWatch.

## Key Engineering Decisions

### Private S3 Instead of Public Website Hosting

The frontend S3 bucket is not publicly accessible. CloudFront retrieves frontend objects using Origin Access Control, allowing the application to provide public HTTPS access without exposing the underlying S3 bucket.

### Public Reads and Authenticated Writes

Resource information can be viewed without authentication, while operations that modify application data require a valid Cognito-issued JWT.

Authorization is enforced by API Gateway rather than relying on frontend controls.

### OAuth Authorization Code with PKCE

The browser application does not store a Cognito client secret. PKCE provides an OAuth flow appropriate for a public browser client by binding the authorization request to the subsequent token exchange.

### Least-Privilege Lambda Permissions

The Lambda execution role is limited to the DynamoDB operations currently used by the application. Permissions for unused DynamoDB query operations and secondary-index resources are not granted.

### Terraform-Generated Frontend Configuration

AWS-generated resource identifiers change when infrastructure is recreated. Terraform therefore generates the frontend deployment configuration from actual resource attributes rather than requiring those values to be hardcoded into the application.

### Terraform-Managed CloudWatch Logs

The Lambda CloudWatch log group is explicitly managed through Terraform with a defined retention period, making logging behavior part of the infrastructure configuration rather than relying on an automatically created unmanaged resource.
